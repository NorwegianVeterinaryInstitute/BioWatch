📅 BioWatch — 2025-12-07 to 2025-12-21

🚀 Section A: Command-Line & Secure Analytical Tools (Newest First)

- **CORAL** (Release Date: 2025-12-08) #assembly #annotation #snakemake
    - Links: [GitHub](https://github.com/EvoDevoGenomics-UB/CORAL) | [bioRxiv preprint](https://doi.org/10.1101/2025.12.04.692336)
    - Function: A Snakemake workflow for annotating compact, fast-evolving eukaryotic genomes directly from long-read RNA-seq, bypassing the short-read-based gene models that tend to under-call exon structure in highly derived genomes. Demonstrated on *Oikopleura dioica*, a tunicate with one of the most compact chordate genomes known.
    - Use Case: Genome annotation for species whose genomes have undergone extreme compaction or rapid structural turnover — directly relevant to any non-model host, vector or pathogen genome where standard annotation pipelines (trained on well-behaved reference genomes) perform poorly.
    - Usability Note: MIT license, comprehensive README, 154 commits. A companion tool (GAMBA, for downstream analysis) is cross-linked in the same code-availability statement. Too new (first posting this cycle) to assess issue-responsiveness.

- **CycSim** (Release Date: 2025-12-08) #assembly #python
    - Links: [GitHub](https://github.com/BioEarthDigital/CycSim) | [Bioconda](https://anaconda.org/bioconda/cycsim) | [bioRxiv preprint](https://doi.org/10.1101/2025.12.04.692264)
    - Function: A context-aware long-read simulator that learns k-mer-dependent error profiles from real sequencing data, paired with a Bayesian-optimization framework to systematically tune long-read mapping parameters rather than relying on tool defaults.
    - Use Case: Squeezing out mapping accuracy for difficult/repetitive genome regions (e.g. parasite or pathogen genomes with high repeat content) by calibrating aligner parameters to the actual error profile of a given instrument run instead of generic presets.
    - Usability Note: MIT license, README covers installation/training/benchmarking, 36 commits, Bioconda recipe available. Issue-responsiveness not yet assessable (first release this cycle).

- **AEGIS** (Release Date: 2025-12-08) #annotation #comparative-genomics #python
    - Links: [GitHub](https://github.com/Tomsbiolab/aegis) | [PyPI](https://pypi.org/project/aegis-bio/) | [Docker](https://hub.docker.com/r/tomsbiolab/aegis) | [bioRxiv preprint](https://doi.org/10.1101/2025.12.04.692274)
    - Function: A Python toolkit that parses, validates and standardises GTF/GFF3 genome-annotation files — which vary enough in formatting between sources to create real downstream-analysis bottlenecks — then layers on feature extraction, annotation merging, and comparative genomics (orthology, synteny) between annotation sets.
    - Use Case: Cleaning up and reconciling annotation files pulled from different sources/pipelines before cross-genome comparison — a recurring friction point for anyone doing comparative or pangenome work across non-uniformly annotated reference genomes.
    - Usability Note: GPL-3.0 license, README + PyPI package + Docker image, CI via GitHub Actions validating every commit — a stronger maintenance signal than most new tools get at this stage, though real-world issue-responsiveness still unconfirmed this early.

💡 Methodological Trend

An incremental but practically important AMR methods-validation signal (focus area 2/9) this cycle: Mukiri, Alcock, Raphenya & McArthur (McMaster/CARD group) released a systematic evaluation of over- and under-prediction in the **Resistance Gene Identifier (RGI)**, the prediction engine behind the widely-used CARD database, adding a previously-unreported alignment statistic (percent positive) to the RGI v5.2.1 codebase and quantifying where genotype-only AMR calls diverge from phenotype ([bioRxiv, posted 2025-12-15](https://doi.org/10.1101/2025.12.11.693720)). Not a new standalone tool, so no separate Section A/B entry, but worth flagging for anyone treating RGI/CARD output as ground truth for AMR gene calls — this is the kind of accuracy audit that doesn't get much visibility outside the AMR-informatics community itself.

ℹ️ Section B: Informational & Proprietary

- **RAmpSim** ([GitHub](https://github.com/az002/RAmpSim) | [bioRxiv preprint](https://doi.org/10.1101/2025.12.05.692407)) — no declared license #metagenomics #emerging
    - Function: A Rust-implemented thermodynamic simulator (nearest-neighbor energy model, Boltzmann-weighted bait-binding) for hybridization/bait-capture metagenomic sequencing, reproducing real within-genome coverage and cross-species enrichment patterns an order of magnitude better than uniform-coverage baselines. README present, 30 commits, but no LICENSE file found in the repository — fails this report's strict Section A usability bar despite otherwise looking like a solid benchmarking tool for capture-panel design (relevant to targeted AMR/pathogen panel work).

    - Function: Chiara, Alfonsi, Ceri, Ferrandi & Bernasconi apply the existing HaploCoV workflow to 26,930 complete H5N1 genomes, finding that North American spillover lineages carry ==distinctively elevated diversity in the PA/PB2/NP ribonucleoprotein-complex segments relative to viruses elsewhere — a candidate genomic signature for mammalian-adaptation risk.== [SURVEILLANCE-READY] (H5N1 is an ECDC/EFSA/NVI priority pathogen); no new code release, HaploCoV itself predates this window.
