- **metaspades-memory-prediction** (Release Date: 2026-05-13) #metagenomics #python
    - Links: [GitHub](https://github.com/usegalaxy-eu/metaspades-memory-prediction) | [bioRxiv preprint](https://doi.org/10.64898/2026.05.12.724571)
    - Function: Zierep, Faack, Beracochea, Sanchez, Batut, Finn, Gruening (EBI MGnify / Galaxy Europe) built a machine-learning framework — Gaussian-process regression over k-mer and input-file-size features — that predicts the peak memory a metaSPAdes metagenomic assembly job will need, evaluated with a production-oriented cost function that accounts for HPC retry policies and resource waste rather than plain regression error.
    - Use Case: Right-sizing memory allocation for metagenomic assembly jobs on shared HPC/Galaxy infrastructure — reduces both job failures from under-allocation and wasted GPU/CPU-hours from over-allocation, directly reusable by any lab running metaSPAdes at scale (wastewater/environmental surveillance pipelines included).
    - Usability Note: MIT license, README and requirements.txt present, 11 commits, 0 stars — from the established Galaxy Europe/EBI MGnify infrastructure team; too new and low-traffic to assess issue-responsiveness this run, but the surrounding Galaxy ecosystem has a strong maintenance track record.

- **detox / HaploDetox** (Release Date: 2026-05-12) [EXPERIMENTAL] #metagenomics #variant-calling
    - Links: [GitHub](https://github.com/biointec/detox) | [bioRxiv preprint](https://doi.org/10.64898/2026.05.11.724222)
    - Function: Steyaert, Van Hecke, Marchal, Fostier (Ghent University, biointec) built a C++ tool that reconstructs bacterial strain haplotypes de novo from a de Bruijn graph of short reads, labelling nodes/arcs with a Conditional Random Field that incorporates neighbouring-node context rather than scoring k-mers independently.
    - Use Case: Recovering distinct strain haplotypes from a mixed bacterial sample (e.g. a polyclonal infection or environmental/wastewater metagenome) without a reference — a de novo alternative to reference-based strain-deconvolution tools for metagenomic/outbreak samples containing more than one strain of the same species.
    - Usability Note: AGPL-3.0, comprehensive README (install, usage, parameters), 6 commits, 4 stars, CMake source build only (no conda/Docker). The README itself flags the tool as "experimental, but functional" and notes the companion assembly-pipeline paper is still under review — too young to assess issue-responsiveness.

- **IndaDiaz2026__ARGTools** (Release Date: 2026-05-12) #amr #one-health #snakemake
    - Links: [GitHub](https://github.com/BigDataBiology/IndaDiaz2026__ARGTools) | [bioRxiv preprint: "The elusive resistome"](https://doi.org/10.64898/2026.05.11.724158) | [Zenodo data](https://zenodo.org/uploads/19702877)
    - Function: Inda-Díaz, Adegoke, Löber, Jarquín-Díaz, Duan, Bengtsson-Palme, Ugarcina Perovic, Coelho (Centre for Microbiome Research QUT / Max-Delbrück-Center / Chalmers / BigDataBiology lab) packaged Snakemake workflows that run six widely-used ARG-detection pipelines (DeepARG, RGI, fARGene, ResFinder, AMRFinderPlus, ABRicate) side by side over the Global Microbial Gene Catalog (270M+ genes, 11,519 metagenomes, 13 habitats), harmonising outputs with argNorm, plus the R scripts behind the paper's figures and an interactive companion web app.
    - Use Case: A reusable harness for anyone who needs to pick or validate an AMR-gene-detection pipeline for metagenomic surveillance — the paper's headline finding (reported ARG counts vary up to 45-fold between pipelines, mean pairwise Jaccard index only 16%) is itself a strong argument for running more than one tool and checking agreement, exactly the kind of check a human-animal-environment AMR surveillance pipeline should budget for.
    - Usability Note: MIT license, README present, 259 commits — from an established metagenomics lab (Luis Pedro Coelho/BigDataBiology, known for NGLess, SemiBin) with a strong maintenance track record; this specific repo is new this cycle so issue-responsiveness wasn't checked individually.

💡 Methodological Trend

Two independent releases this cycle push structure-aware deep learning into host-pathogen *interaction* prediction rather than single-protein function — a focus-area-10 angle distinct from the LLM-agent-wrapper wave tracked in recent cycles. **GeoEPred** (Song, Shi, Wu et al., posted 2026-05-18, [code](https://github.com/shouzhensong/GeoEPred)) couples a pretrained protein language model with a geometric-vector-perceptron structural encoder to predict which proteins a Gram-negative bacterium secretes through its Type III/IV/VI secretion systems — directly relevant to characterising virulence in any Gram-negative veterinary or zoonotic pathogen, though the repo currently ships no LICENSE file, so it stays out of Section A pending that being added. In the same vein, the **Klebsiella phage receptor-binding-protein atlas** (Panicker, Smug, Klein-Sousa et al., Mostowy lab, first posted 2026-05-12, [interactive atlas](https://vyshakhrp.github.io/klebsiella-rbp-atlas)) used AlphaFold3 modelling across 382 receptor-binding proteins from 192 *Klebsiella pneumoniae* phages to resolve six structural host-recognition strategies — a directly reusable reference for phage-therapy host-range engineering against this WHO-priority MDR pathogen, again released as open data/HTML without a LICENSE file. Together with last cycle's PanBART and OrionGeno/Tiberius convergence, structure-first (rather than homology-first) characterisation of bacterial virulence and phage-host interaction looks to be consolidating into a standard move — worth watching for whether these specific tools gain a proper license and move into Section A next time they're checked.
