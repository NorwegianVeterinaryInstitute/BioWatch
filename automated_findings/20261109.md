🚀 Section A: Command-Line & Secure Analytical Tools (Newest First)

- **VenusGenome** (Release Date: 2026-10-24) #plm #emerging [EXPERIMENTAL] #python
    - Links: [GitHub](https://github.com/zhangliang-sys/VenusGenome) | [HuggingFace](https://huggingface.co/z-liang/VenusGenome-85M) | [bioRxiv preprint](https://www.biorxiv.org/content/10.64898/2026.10.24.761516)
    - Function: A masked-autoencoder genome encoder that contextualizes gene-level ESM-2 protein embeddings across a whole microbial genome, producing gene- and genome-level representations. The pipeline matches GFF CDS features to FAA proteins, generates per-protein ESM-2 embeddings, then runs VenusGenome on the ordered embedding sequence.
    - Use Case: Microbial genome function/representation learning from existing protein-level embeddings, e.g. for downstream phenotype or AMR-association prediction without retraining a sequence model from scratch.
    - Usability Note: [EXPERIMENTAL] — HuggingFace page states no declared open-source model-weight license; GitHub repo exists (`release/inference-v1` branch) but maintenance/issue activity not independently confirmed this run. Requires upstream gene calling + ESM-2 embeddings, not a standalone sequence-in tool.

- **flodl-bio** (Release Date: 2026-10-21) #emerging #cross-domain [EXPERIMENTAL]
    - Links: [GitHub](https://github.com/sablokg/flodl-bio) | [bioRxiv preprint](https://www.biorxiv.org/content/10.64898/2026.10.21.760383)
    - Function: A Rust crate extending `flodl` (a libtorch-backed deep-learning framework) with alphabet-aware sequence encoding, FASTA utilities and neural architectures for deep learning directly on biological sequences, bypassing the Python stack.
    - Use Case: Groups wanting GPU-backed sequence modeling (classification, embedding) in a Rust pipeline rather than Python/PyTorch — relevant where throughput or deployment constraints rule out a Python dependency.
    - Usability Note: MIT license confirmed. [EXPERIMENTAL] — first release (v1), requires Rust ≥1.91 and NVIDIA/libtorch; no maintenance history yet to assess responsiveness.

💡 Methodological Trend

Two threads worth flagging from this cycle, both relevant to surveillance-grade work rather than a single flashy tool:

- **Fast genotyping tools may misrepresent true evolutionary relationships.** McLaughlin et al. (bioRxiv, posted 2026-10-30) systematically compared genetic-similarity-based H5Nx genotype assignments (as produced by tools like GenoFlu and Genin2) against global phylogenies, and found only 14.2% of GenoFlu-defined clusters were monophyletic. Their conclusion: these tools are "rapid, stable, and sufficient for broad categorization, but may group viruses with distinct evolutionary histories and fail to assign divergent viruses, risking biased surveillance, modeling, and risk assessment." Worth a flag for anyone using genotype-assignment output directly as a proxy for phylogenetic relationship in H5N1 surveillance reporting — [SURVEILLANCE-READY] territory (ECDC/EFSA/NVI priority pathogen) but a methodological caveat, not a tool recommendation.
- **Protein-embedding-based genome models keep spreading from single proteins to whole genomes.** VenusGenome (above) is the latest in a growing set of models (alongside e.g. a multispecies genome foundation model and plant-genome foundation models seen in preprints this cycle, not separately detailed here) that treat a genome as a sequence of pre-computed per-protein language-model embeddings rather than raw nucleotides. For AMR/functional-annotation work this increasingly means "bring your own ESM-2 embeddings" pipelines rather than end-to-end sequence tools — a shift worth tracking for tooling compatibility.
