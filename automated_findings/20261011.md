- **Kingdom-wide Discovery of Type VI Secretion Effectors via AI** (Release Date: 2026-09-28) [EXPERIMENTAL] #amr #emerging #python

    - Use Case: A kingdom-scale screen for novel bacterial toxin/virulence-factor families from sequence alone, relevant to anyone characterizing competitive fitness or virulence potential in bacterial isolates (e.g. AMR/virulence co-occurrence screening) rather than relying on known Pfam/effector databases.

- **CheckAMG** (Release Date: 2026-09-27) #disease-x #plm #python
    - Links: [GitHub](https://github.com/AnantharamanLab/CheckAMG) | [bioRxiv preprint](https://www.biorxiv.org/content/10.64898/2026.09.23.753886) | [PyPI](https://pypi.org/project/checkamg/)
    - Function: Anantharaman Lab (UW-Madison) built a tool that identifies auxiliary viral genes (metabolic/regulatory/physiology genes viruses carry to reprogram host metabolism during infection) using Protein Set Transformer, a genome-language model pretrained on >100k dereplicated viral genomes, combined with genome-context-based curation — replacing ad hoc annotation-based AMG calling.
    - Use Case: Directly useful for "viral dark matter" / disease-X discovery pipelines that need to distinguish genuine host-reprogramming viral genes from annotation artifacts when characterizing novel phage or eukaryotic-virus genomes from metagenomic data.

💡 Methodological Trend

Two of this cycle's four new tools (the T6SS effector screen and CheckAMG) are variations on the same move: training/applying a model across a large genome collection to surface biology that classical homology search would miss — previously unannotated bacterial toxins in one case, ambiguous viral auxiliary genes in the other. This continues a thread flagged in [[20260927]] (protein-embedding genome models) from a different angle: rather than new embedding architectures, this cycle's examples are about using existing modeling approaches (a genome-language model, a straightforward ML classifier) at kingdom/pangenome scale to mine for rare, previously-missed functional categories.

Separately, a usability pattern worth tracking on BioWatch's own terms: two of this cycle's four Section A tools (BiomiX 3.0, the T6SS effector project) have otherwise-active, well-documented code but **no LICENSE file at all** — not a restrictive license, just none. That's a different (and for reuse purposes, worse) problem than the "non-standard license" issue flagged for other tools in past cycles, since it leaves reuse rights genuinely undefined rather than merely restricted.
