📅 BioWatch — 2026-01-18 to 2026-02-01

🚀 Section A: Command-Line & Secure Analytical Tools (Newest First)

- **DecoDiPhy** (Release Date: 2026-01-21) #metagenomics #phylogenetics #python
    - Links: [GitHub](https://github.com/shayesteh99/DecoDiPhy) | [bioRxiv preprint](https://doi.org/10.64898/2026.01.18.700179) | [Bioconda](https://anaconda.org/bioconda/decodiphy)
    - Function: Arasti, Mirarab et al. (UC San Diego) formalize "phylogenetic distance deconvolution" (PDD) — placing a mixed/metagenomic sample on multiple branches of a reference phylogeny at once, with abundances, rather than forcing one placement per read — and implement exact and fast heuristic solvers in the Python tool DecoDiPhy.
    - Use Case: Consolidating millions of noisy per-read phylogenetic placements (the usual output of metagenomic classifiers against a reference tree) into a small, interpretable set of taxon placements with abundance estimates — relevant to any taxonomic-profiling or strain-mixture step in a metagenomic surveillance pipeline.
    - Usability Note: MIT license, README with Colab tutorial, Bioconda recipe, 52 commits. Too new (first posting this cycle) to assess issue-responsiveness.

- **FastSpeciesTree** (Release Date: 2026-01-21) #phylogenetics #evolution
    - Links: [GitHub](https://github.com/OrthoFinder/FastSpeciesTree) | [bioRxiv preprint](https://doi.org/10.64898/2026.01.20.700630)
    - Function: Holmes & Kelly (University of Oxford, OrthoFinder group) present a fully-automated species-tree method that builds pseudo-alignments from overlapping BLAST hits across BUSCO-identified single-copy orthologs, then infers the tree with a fast (VeryFastTree) or sensitive (IQ-TREE) mode — reported to tree the near-entirety of RefSeq's proteomes (n=33,285) in under 12 hours on standard hardware.
    - Use Case: Fast, large-scale species-tree inference directly from raw proteome files — useful wherever a pangenome, comparative-genomics or AMR-gene-family study needs a backbone phylogeny across hundreds-to-tens-of-thousands of genomes without hand-curating single-copy orthologs first.
    - Usability Note: GPL-3.0 license, README covers install/fast vs. sensitive modes, 31 commits, 1 open issue (maintainer-responsiveness not yet confirmed, part of the actively-maintained OrthoFinder ecosystem). Project notes it is "ongoing, with potential workflow changes."

- **PePApipe** (Release Date: 2026-01-14) [SURVEILLANCE-READY] #assembly #variant-calling #one-health
    - Links: [GitHub](https://github.com/vilocha/PePApipe) | [bioRxiv preprint](https://doi.org/10.64898/2026.01.12.698977) | [Protocol](https://www.protocols.io/view/pepapipe-complete-bioinformatics-analysis-pipeline-261geeo57g47/v1.pdf)
    - Function: Lopez-Chavarrias, Fernandez-Pinero et al. (CISA-INIA-CSIC) built a Python, bash/SLURM-driven pipeline integrating 13 tools (QC, de novo assembly incl. RagTag/MeDuSa scaffolding, variant calling) into one automated workflow specifically for African Swine Fever Virus (ASFV) genomes, aimed at laboratory staff with only basic command-line experience.
    - Use Case: Standardised, low-bioinformatics-overhead ASFV genome assembly and variant-calling straight from raw sequencing reads — directly relevant to NVI/EFSA-priority ASF surveillance, and the authors note it is adaptable to other viral pathogens. [SURVEILLANCE-READY] (ASF is an EFSA/NVI priority pathogen).
    - Usability Note: GPL-3.0 license, comprehensive README, 73 commits, no open issues visible. Too new (first posting this cycle) to assess issue-responsiveness; already accepted for publication in *PLOS ONE* (preprint's companion journal article), a stronger-than-average maturity signal for a brand-new tool.

💡 Methodological Trend

The focus-area-10 (emerging & cross-domain) wave of self-directed "omics AI agents" flagged in the 2026-01-18 cycle ([[20260118]]: ToolsGenie 2.0, NetMedGPT, BiomeGPT) continued this cycle with at least three more entrants. **Medea** (Sui, Zitnik et al., Harvard, posted 2026-01-16) is a multi-agent system that plans, executes and verifies multi-step omics analyses for therapeutic-target discovery (target ID, synthetic lethality, immunotherapy-response prediction), and — unlike last cycle's agents — has a real, Apache-2.0-licensed GitHub release ([mims-harvard/Medea](https://github.com/mims-harvard/Medea), 41 commits) with CLI and library usage documented; it's excluded from Section A here because its benchmarks and target applications are human-oncology/immunotherapy specific rather than pathogen/AMR-relevant, but the pattern (agent frameworks moving from preprint-only to real code releases) is worth tracking. **BiOmics** (Cao et al., posted 2026-01-17) is a similarly-architected tripartite agent (knowledge graph + toolchain + orchestrator) for autonomous multi-omics interpretation, but no public code repository could be confirmed this run. **PersonaAI** (Cho et al., posted 2026-01-16) is a third agentic-AI framework, this one for hypothesis generation/validation in aging research — also no confirmed code release. Taken together: agent-based "AI does the bioinformatics" systems are maturing from pure preprints towards real, licensed repositories, but the ones with working code so far target human biomedicine, not yet pathogen/AMR surveillance.
